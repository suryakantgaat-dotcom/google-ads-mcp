# Post types

Pick one type per post. Each lists the inputs it needs from the user and a skeleton. The skeletons are working structures (level I). No source compares these structures head to head, so do not claim one outperforms another.

Default format for each is text (about 1,200 to 1,500 characters) unless noted. Move reference-style content (frameworks, checklists, teardowns) to a document, per R7.

## Contents

1. Experiment write-up
2. Case study
3. Teardown
4. Contrarian take
5. Framework

## 1. Experiment write-up

Needs: hypothesis, the one variable changed, setup (platform, campaign type, budget band, duration), baseline metric, result, sample size or conversion count per variant, the caveats, what the user would change.

Skeleton:
1. Hook: the result or the surprising null, with the number.
2. What we tested and why (one or two lines).
3. Setup and baseline.
4. Result, with the significance caveat in plain words.
5. What this does not show.
6. What I would do differently.
7. Close: one specific question, or none.

Publish nulls. A null with a clear setup is evidence; Search Engine Land experiment write-ups model this (not read).

## 2. Case study

Needs: client permission status (see the checklist), the problem as the client saw it, what the user did, baseline and result with the window, what else changed during the period, what was typical versus atypical.

Skeleton:
1. Hook: the problem in the buyer's terms, with a number if permitted.
2. Situation and baseline.
3. The decision that mattered, and the alternative not taken.
4. Result and window.
5. Confounders and limits.
6. What transfers to other accounts and what does not.

If results are atypical, say what is typical. Disclaimers like "results not typical" do not satisfy the FTC rule on their own (Morgan Lewis, not in the verification pass).

## 3. Teardown

Needs: the object (the user's own account, a public ad from the Meta Ad Library or Google Ads Transparency Center, a public landing page), what the user can observe versus infer, the user's judgment.

Skeleton:
1. Hook: the one flaw or choice worth noticing.
2. What is visible, stated as observation.
3. What it probably means, marked as inference.
4. What the user would test first.
5. Close.

Do not present inferences about someone else's spend, targeting or results as fact. Do not teardown a named client's private account without permission. Best as a document when it has more than three points.

## 4. Contrarian take

Needs: the common belief, the user's opposing view, the evidence from the user's own work, and the condition under which they would change their mind.

Skeleton:
1. Hook: the claim, stated plainly.
2. Why most people believe the opposite (fairly).
3. The evidence, with numbers from the user.
4. Where the claim breaks.
5. What would change my mind.

Contrarian only with evidence. Without it, it reads as a slogan (practitioner sources, level C).

## 5. Framework

Needs: the decision the framework helps with, the criteria and why each matters, one worked example with real numbers from the user, where it fails.

Skeleton (document or carousel):
1. Slide or line 1: the decision and who it is for.
2. One criterion per slide, each with the reason and a threshold the user actually uses.
3. A worked example.
4. When not to use it.
5. Close.

A framework with no worked example and no failure case is generic advice. Ask for both.
